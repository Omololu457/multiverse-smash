METHODOLOGY
  - Playable = characters where isPlayable !== false  (characters.js).
  - Skin count = the length of that character's array in the SKINS
    registry (skins.js), which INCLUDES the "Default" entry (Default is a
    selectable skin on the skin-select screen, so it is counted).
  - A character with NO entry in the SKINS registry has ZERO real skins;
    the game hands them a single synthetic "Default" at runtime via the
    getSkins() fallback, but nothing is authored in the registry.

WHAT THE 3 SKINS ARE
  - Albedo   = black garment / red accent / grey trim  (Yuta's EXACT palette)
  - Valkyrie = light-blue garment / gold accent+trim    (Yuta's EXACT palette)
  - Alien X  = matte-black void base + procedural colourful starfield overlay
               (game.js drawAlienXStarfield, gated on skinId ending "AlienX")

TOOLING (reuse these — do NOT reinvent)
  - Generator: tools/gen_underskin_recolor.py  (per-char classify() fns +
    the 3 palettes; ALWAYS generate from the char's EXACT animationData sheet
    list, never a glob — globbing overwrites existing skins / grabs junk).
  - Live verify: harness/underskin_shots.mjs  (add char to CONFIG; checks it
    renders the recoloured __tag sheet on idle/walk/light/heavy, no boxes,
    Alien X overlay runs; form-aware chars get SSJ/form checks).
  - Alien X overlay already wired + reusable (skinId endsWith "AlienX").

PER-WAVE PRE-CHECK (learned the hard way — do this BEFORE generating):
  1. TAG COLLISION: some chars already have a creative skin using tag
     "albedo"/"valkyrie"/"alienx" (e.g. rengoku/shinobu "Albedo Protocol",
     gojo "Albedo Protocol", toji "Royal Valkyrie", yuta Albedo+Valkyrie).
     Generating those tags OVERWRITES their existing sheets. -> skip that
     tag for that char (give only the missing ones), or it collides on id.
     After generating, run: git status --porcelain <char>_*__<tag>.png
     -> any ' M' means you clobbered an existing file (git checkout to undo).
  2. .jpg PORTRAITS: some portraits are .jpg (e.g. sukuna_portrait.jpg).
     Output name MUST be re.sub(r'\.(png|jpe?g)$','__<tag>.png') -> PNG.
     (A naive .replace('.png',...) tried to save RGBA as .jpg and CORRUPTED
     sukuna_portrait.jpg once; restored via git checkout.)
  3. MISSING BASE SHEETS: some animationData refs a file that isn't on disk
     (e.g. sukuna_hurt_sheet.png). Skip non-existent base sheets (os.path.exists).
  4. FORM-AWARE chars: set recolorTag on the skin entry so retagFormAnim
     recolours the transform sheets too, and generate those form sheets
     (Vegeta SSJ/Blue, Goku SSJ/SSG/SSB, Gohan SSJ2, Goku-Black + Vegeta-Dark
     Rose, Maki Shibuya were done this way).
  5. ALREADY-BLACK chars: Albedo reads ~identical to Default -> drop Albedo,
     give Valkyrie + Alien X only (precedent: Boruto, Vegeta Dark, Alt Sukuna).
