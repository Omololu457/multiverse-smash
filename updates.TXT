File: combat.js — the single shared HITSTOP table (combat.js:81).
Every melee AND projectile freeze routes through this ONE table via
getHitstopFrames()/getProjectileHitstopFrames() → applyHitstop(), so this
is a pure global tuning change; no per-character hitstop code exists.

LIGHT-tier freeze deliberately left UNCHANGED (jabs stay snappy).

  Tier        BEFORE   AFTER    note
  light         4        4      unchanged (snappy pokes)
  air           4        4      unchanged (light-weight aerial)
  grab          6        6      unchanged
  heavy         8       10      big normals land with more weight
  launcher      8       12      a launch now reads heavier than a plain heavy
  spike         8       12      kept == launcher (same finisher-weight family)
  special      12       16      specials feel expensive

  projectile    8        8      unchanged (zoner-friendly)
  parry        14       14      unchanged
  clash        14       14      unchanged

Why this is combo-safe: applyHitstop() freezes BOTH attacker and defender
(via max()), so the attacker's own recovery is paused for the same window

preserved, only the absolute wall-clock of the freeze grows. No cancel
window or buffer value was touched.

   frame a fighter's HP first hits 0 (health-KO only; a time-over does
   NOT get the beat). Reuses the EXISTING slowdown primitive (triggerSlow

   — so it delivered no real focus. Changed to ease a tight zoom-IN

   a smooth push not a snap), and gated the normal two-fighter reframe while
   the KO hang is active so the punch-in actually holds. This primitive was
   confirmed to have NO other live callers, so repurposing it is safe.

   FFA/TEAM elimination (game.js checkFFAOutcome): bumped the elimination
   shake 10/8 → 26/26 (KO_SHAKE constants) for consistency. Deliberately
   NO slow-mo hang there — a live 3–4-player match shouldn't stall on every
   drop; only the 1v1 finishing blow gets the hang.

   BEFORE → AFTER (KO/ult vs a routine hit):

     routine special beat ................. ~6–12 shake, ~0.95–1.0 zoom (UNCHANGED)
     ULTIMATE connect (global floor) ...... shake 16/18 + 1.05 zoom-in   (NEW)

STAGE 3 — SMOOTHER CAMERA EASING (neutral <-> hit-confirm)        [DONE]
────────────────────────────────────────────────────────────────────────
File: camera.js — the shared advance() interpolation used by BOTH the
neutral two-fighter framing (update/updateMulti) AND every hit-confirm/
special/domain focus (focusBetween/focusOnFighter → advance). One place,
so the change is global and consistent.

FINDING (verification part): the transition was NOT a hard cut and NOT a
fixed-duration linear tween. It already used lerp(current, target, smooth)
= an exponential EASE-OUT toward the target. So the settle was already
eased. The one rough spot was the per-frame RATE LIMIT: the old code hard-
clamped the step to a fixed ceiling —
    nextZoom = zoom + clamp(lerpStep, -zoomStep, zoomStep)     // hard cap
    nx       = x    + clamp(lerpStep, -maxPanStep, maxPanStep) // hard cap
For any transition big enough that the lerp step exceeded the ceiling, the
camera ran at a CONSTANT max rate (a linear segment) and then abruptly
handed off to the ease-out — a visible "kink"/snap on larger reframes.

CHANGE (contained — the interpolation function only): replaced the hard
clamp with a SOFT, eased rate-limit:
    function softStep(delta, cap) { return cap>0 ? cap*Math.tanh(delta/cap) : delta }
    nextZoom = zoom + softStep(lerpStep, zoomStep)
    nx       = x    + softStep(lerpStep, maxPanStep)   // same for ny
tanh(x) ≈ x for small steps, so the small neutral↔hit-confirm zoom changes
keep the existing ease-out almost exactly; it saturates to ±cap for big
steps, so a large reframe now ACCELERATES smoothly into the ceiling and
DECELERATES out of it — the linear kink is gone. |tanh| < 1 guarantees the
step never exceeds `cap`, so the original anti-pop/anti-jerk safety is kept
(actually slightly tighter). Deterministic — no RNG, no new state.

Numeric proof (cap = zoomStep = 0.02):
    delta 0.001 → hard 0.0010 / soft 0.0010   (hit-confirm: unchanged)
    delta 0.008 → hard 0.0080 / soft 0.0076   (near-cap: gently eased)
    delta 0.020 → hard 0.0200 / soft 0.0152   (kink region: smoothed)
    delta 0.050 → hard 0.0200 / soft 0.0197   (large: same ceiling)
    delta 0.200 → hard 0.0200 / soft 0.0200   (huge: same ceiling)
    every soft step strictly within ±cap.

The deliberate one-shot SNAPS (giant-form first-frame reveal in update(),
match-start snap in updateMulti) are untouched — those set zoom/x/y
directly and never route through the softened step, exactly as before.

Verify:
  node --check camera.js → OK
  softStep numeric table above (hard vs soft) → matches intent
  Camera is cosmetic (reads fighter positions, writes only camera fields +
  Math.random for shake) so it cannot affect sim determinism by construction;
  npm run test:determinism stays 9/0 (re-confirmed in the final report).
  No existing camera/framing unit test exists in package.json to run.
