PLAYTEST FIXES — MOVE LIST stuck/scroll + arcade energy drain — 2026-09-20
Two bugs reported by playtesters. Purely UI + one mode-setup line; combat.js
UNTOUCHED; determinism unaffected. Committed + pushed origin/main @8f314997.
========================================================================

BUG 1 — MOVE LIST screen: BACK unclickable (players STUCK) + no scrolling.
  The MOVE LIST ("Fighters, moves, combos & controls") screen lists ~103
  fighters in a column far taller than the viewport. Its off-screen rows
  overlapped the BACK / CONTROLS buttons, and the click handler tested the
  fighter rows BEFORE the buttons — so clicking BACK hit an off-screen row
  instead and did nothing (keyboard Esc still worked; only MOUSE users were
  stranded). FIX: (a) hit-test the buttons FIRST, and only make fighter rows
  clickable within the scrolled viewport; (b) the fighter list AND the kit
  panel now SCROLL (mouse wheel, with scrollbars) so the whole roster and a
  character's full move list are reachable.
  Files: ui.js (viewport/scroll helpers + clipped list + scrollable kit
  panel), game.js (scroll state + wheel routing + buttons-first hit-test).

BUG 2 — Arcade: "lose all your energy and can't regain it."
  applyArcadeFight() never cleared matchConfig.modifiers (unlike
  applyTowerFloor, which assigns them per floor), so a leftover match
  modifier — most damagingly a Tower floor's "Meter Drain" (−0.5 energy/
  frame, vs +0.06/frame regen) — PERSISTED onto every arcade fight and
  pinned the player's meter at 0. Arcade is designed to run clean. FIX: one
  line — applyArcadeFight now clears matchConfig.modifiers for every fight.
  Proven: with the drain set, energy fell −50..−75 in ~2s and stuck; after
  the fix it clears and regenerates normally.

VERIFY: new test:movelist-arcade-fix 12/0 (real BACK click through the
  canvas, wheel scroll, arcade modifier-clear + energy regen). Regression:
  determinism 9/0 · combo-standard 227/0 · arcade 25/0 · tower 38/0 ·
  controls-help 5/0.

WHY THE REBUILD
  The screen-flash version fired correctly but was a 2-6 frame full-screen
  effect — nearly impossible to catch in a live/human-timed screenshot, so
  it "looked like nothing". Diagnosis (Stage 1): NOT a bug (the impactFrame()
  hook returned a live marker on every real hit; it just needed a frame-exact
  capture to see). So the trigger stayed; the TECHNIQUE was replaced.

WHAT IT DOES NOW
  At hit-connect BOTH the struck + striking fighters' SPRITES snap (2-5f) to
  a stark, rough "Black Flash" recolor: a hard high-contrast CHARCOAL body
  (ctx.filter grayscale + crushed contrast — reads on any character's palette)
  with a flat cursed-RED silhouette (#c8102e — the exact Black-Flash red from
  Yuji's ultimate, yujiUltimateCinematic.js) washed over it. Then back to
  normal, layered on the existing hitstop freeze. A stark POP, not a wash.

ESCALATION (visual only) — level = min(3, comboTier + hit-weight), where
  comboTier mirrors the 5 / 9 / 15 combo-counter tiers and heavier hits
  (heavy/special/ultimate) bump a notch. Higher level → deeper contrast,
  darker, redder wash, and longer hold (2f base → 5f at 15+). comboCounter
  is READ-ONLY.

GATED OFF during a Brutality — the trigger and the per-frame tick both bail
  on brutalityState.active, so the finisher palette never clashes.

REUSES EXISTING INFRA (no new render primitives): the sprite.js spriteFilter
  ctx.filter path — the SAME one Goku's form tints (GOKU_FORM_TINTS) and
  Frieza Golden/Black use — plus the source-in silhouette mask from the
  ghostface identity-swap tint (idTint), for the flat red overlay.

IMPLEMENTATION — game.js + sprite.js. triggerImpactFrame (fired on the combo
  rising-edge in updateComboDisplay) stamps a render-only fighter._impactFlash
  marker on both fighters; sprite.js reads it to pick IMPACT_FLASH_TINTS[level]
  + the red overlay while live; _tickImpactFlash counts it down each render
  frame. Determinism-safe: the field is render-only (the determinism harness
  snapshots only x/y/health/energy). NO writes to damage / combo-scaling /
  comboCounter / hitstop state; combat.js UNTOUCHED.

VERIFY (Stage 5, FRAME-EXACT — not live) — rewritten harness/impact_frame_live
  .mjs (test:impact-frame 18/0): marker lands on BOTH fighters, the recolor
  filter actually applies (reads _lastSpriteFilter), tier + combo escalation,
